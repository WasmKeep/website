Get started

From nothing to a counter that survives a restart, with no toolchain, then your first actor in your language. The tutorials in the documentation take it from there.

  1. Install the binary

    On Linux, x86_64 or aarch64 (glibc 2.28 or newer). Name the version: releases are pre-releases for now, so there is no latest.

    {% include "partials/install.html" %}

    Every file of a release is signed: check a download before you trust it. On macOS and Windows, use the image ghcr.io/wasmkeep/wasmkeep:{{ v }} or build from source.

  2. Serve the counter

    A release carries the counter example already built and signed, so this needs no toolchain. In the same shell as step 1, which set $u and $v:

    curl -fsSLO "$u/releases/download/v$v/counter.wasm"
wasmkeep serve --actor counter=counter.wasm

    In another terminal:

    curl -X POST localhost:8080/actor/counter/alice   # 1
curl -X POST localhost:8080/actor/counter/alice   # 2
curl localhost:8080/actor/counter/bob             # 0, a separate actor

    Each name is its own actor with its own SQLite database under .wasmkeep/data/. Restart the server and the counts are still there.

  3. Write your own actor

    Install the SDK of your language, at the version of your server, then follow its guide.

    LanguageInstallStart from
    Rustcargo add wasmkeep-sdkYour first actor in 10 minutes
    TypeScriptnpm install @wasmkeep/sdkits README
    Pythonpip install wasmkeepits README
    Go (TinyGo)go get github.com/wasmkeep/wasmkeep/sdks/go@v{{ v }}its README
    C, Zigthe SDK archive from the releasethe README in each archive

    Then develop with hot reload: wasmkeep dev rebuilds and swaps on every save, keeping the data.

  4. Follow the tutorials

    • Your first actor: a counter with its own database.
    • Your first app: a front and its classes, run with wasmkeep dev.
    • From one node to three: a cluster on one bucket, and a kill.
    • Buckets: which ones are soaked (R2, OVHcloud), and wasmkeep cluster diagnose to check yours before a cluster relies on it.
    • Going to production, and what pre-alpha means for it.

See it survive a kill

The repository's Compose example runs three nodes on one machine, sharing a MinIO bucket, with mutual TLS between them. Kill the node that runs an actor and another restores it from the bucket.
