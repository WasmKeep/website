Get started

Build your first app locally.

Start with a page, an API and a counter that remembers its value. Edit your TypeScript code and see the app rebuild while keeping its data. Release {{ config.extra.release }} is pre-alpha: use it for evaluation, not production.

InstallCreate an appManual SDK setupTutorials

  1. Install the binary

    On Linux, x86_64 or aarch64 (glibc 2.28 or newer). Name the version: releases are pre-releases for now, so there is no latest.

    {% include "partials/install.html" %}

    Every file of a release is signed: check a download before you trust it. On macOS and Windows, use the image ghcr.io/wasmkeep/wasmkeep:{{ v }} or build from source.

  2. Create an app and run it

    With Node.js and npm installed, scaffold the shipped TypeScript app. The directory must be new or empty:

    wasmkeep new my-app --lang typescript --front
cd my-app
npm install
wasmkeep dev

    Open http://127.0.0.1:8080. The scaffold includes a front with a page and an API, an internal counter class, and wasmkeep.toml.

    Its SDK is pinned to your CLI's version. wasmkeep dev rebuilds on save, keeping the data.

    The scaffold is built into the CLI; installing dependencies needs the network. Rust is also supported with --lang rust. See starting a project for the commands and options.

  3. Alternative: set up the SDK yourself

    Install the SDK of your language at the version of your server, then follow its guide. Languages need a toolchain that builds WASI 0.2 components for WasmKeep's interfaces; SDK features vary by language.

  4. Follow the tutorials

    • Your first actor: a counter with its own database.
    • Your first app: a front and its classes, run with wasmkeep dev.
    • From one node to three: a cluster on one bucket, and a kill.
    • Buckets: which ones are soaked (R2, OVHcloud), and wasmkeep cluster diagnose to check yours before a cluster relies on it.
    • Going to production, and what pre-alpha means for it.

See it survive a kill

The repository's Compose example runs three nodes on one machine, sharing a MinIO bucket, with mutual TLS between them. Kill the node that runs an actor and another restores it from the bucket.
